# v0.6.0 candidate

Unreleased candidate, deployed locally on October 26, 2026. Six approved
programmatic inference checks passed on the initial artifact. The later reviewed
artifact passed operational checks and user-reported manual `/compact` in both
clients; it did not repeat the six-request qualification. Publication and broad
desktop GUI qualification are not implied. See the
[deployment report](../deployment-2026-10-26.md).

- Promotes the Windows Codex desktop integration to project-supported status
  within the documented boundary; legacy provider IDs remain compatible.
- Separates immutable production and editable development images/Compose stacks.
- Adds pinned base images/build backend, runtime-only packaging, resource limits,
  log rotation, graceful shutdown, and offline CI/release checks.
- Adds local liveness and per-protocol readiness without changing legacy health shapes.
- Bounds uploads, decoded upstream responses, catalog expansion and concurrency;
  cancels disconnected work and applies overall request deadlines.
- Requires explicit opt-in for synthetic compaction after native 404.
- Configures both Codex clients for harness-managed `/compact`, not the standalone
  compact API; manual completion is user-confirmed in CLI and app.
- Stops advertising unverified optional model capabilities; supports explicit
  per-model overrides after qualification.
- Hardens desktop checks against invalid provider IDs, coercible health fields,
  redirects, unbounded engine probes, and indeterminate process paths.
- Adds synthetic qualification tooling and an explicit live acceptance checklist.

## Upgrade notes

The [subsequent full review](../project-review-2026-10-26.md) fixes encoding
negotiation, cleanup error handling, qualification false positives, lifecycle
failure propagation, CLI configuration merging, and dependency drift gates.
Those follow-up fixes were deployed in the
[approved reviewed-image refresh](../deployment-2026-10-26.md#reviewed-image-refresh).
The local `0.6.0` tag now identifies that reviewed artifact; the previous artifact
is retained under a separate rollback tag.

Production no longer uses source mounts or a `:dev` image. Source changes require
a new image and an approved recreation. Development uses its own Compose file
and port 4142. Tests use the development target, not the production image.

Merge the provider compaction setting for existing clients using the
[compaction guide](../compaction.md). It needs a client reload, not a relay
restart, and does not disable automatic context-limit compaction.

Synthetic compaction defaults off. Missing context metadata now uses a conservative
8192-token limit; missing reasoning tiers and optional capability flags are no
longer guessed. Qualify the actual app/model before enabling overrides.

See [operations](../operations.md) and [release qualification](../compatibility.md)
for deployment, rollback, and remaining acceptance gates.

## Known limitations

- Duplicate assistant text in the desktop UI is tracked as a
  [presumed desktop compatibility issue](../codex-desktop.md#known-issue-duplicate-desktop-output),
  not a proven relay defect. No relay text-deduplication workaround is enabled.
- Clean dependency downloads previously failed at the package-host TLS
  handshake. Cached builds do not resolve that reproducibility gap.
- Hosted CI, comprehensive vulnerability scanning, broader platforms, automatic
  context-limit compaction, and post-compaction tool continuity remain unverified.
