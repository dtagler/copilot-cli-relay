# v0.7.0

Request-size handling and Codex recovery improvements. This release does not
silently truncate conversation history, switch models, or enable synthetic
compaction.

## Changes

- Raises the default upload cap from 16 MiB to **32 MiB**. Explicit
  `COPILOT_MAX_REQUEST_BYTES` settings still take precedence.
- Preserves allowlisted, bounded upstream error codes and parameter names,
  including HTTP 400 `context_length_exceeded`, so Codex can distinguish
  context exhaustion from a generic invalid request.
- Adds opt-in `COPILOT_CODEX_TERMINAL_PAYLOAD_ERRORS=1`. Local and upstream
  Codex HTTP 413 errors become HTTP 400 `request_too_large` errors, avoiding
  the inspected CLI's retryable unexpected-status path. Original status and
  error origin remain in response headers and logs. Claude error behavior
  is unchanged, and byte overflow is never labeled as token-context overflow.
- Adds content-free request-size diagnostics: incoming/outgoing lengths,
  fixed category estimates, near-cap indication, and relay-generated
  correlation IDs. A shared traversal budget prevents complex histories
  from causing unbounded diagnostic work.
- Supports a positive integer `auto_compact_token_limit` in per-model
  `COPILOT_CODEX_MODEL_OVERRIDES`. The advertised threshold is clamped to
  90% of the validated context window (minimum one token). It is absent
  unless configured and does not change model context windows or routing.
- Aligns package metadata and the default production Docker tag at `0.7.0`.
  No dependency versions are changed.
- Documents the generic container contract separately from optional client and
  maintenance tooling. Host installation, networking, credentials, and runtime
  integration remain operator choices.
- Consolidates client and routing terminology into the architecture guide.

## Measured boundaries

On November 18, 2026, bounded synthetic requests sent directly to the Copilot
Responses route with `gpt-6.2-astra` completed at **33,554,432 bytes** and
received HTTP 413 at **33,554,433 bytes**. Larger probes through 64 MiB were
also rejected. The test used a tiny prompt padded with JSON whitespace;
each successful response reported 11 input tokens and 5 output tokens.
This isolates HTTP body size from model context, but does not establish a
universal contract for other routes, models, accounts, or future deployments.

The candidate relay independently passed real-HTTP 32 MiB boundary tests for
Content-Length and chunked uploads, JSON and SSE responses, payload integrity,
and recovery after rejection. A 64 MiB local stress test passed eight concurrent
requests with rewrites, but reached the 1 GiB RAM limit and used approximately
240 MiB of swap. A higher configurable cap is not a memory-safety guarantee
and cannot bypass an upstream cap. These payload tests exercised the same
size-handling implementation before final release packaging; retain the final
artifact checks below.

## Upgrade

1. Build and validate the `0.7.0` production image, preserving the previous
   image under a unique rollback tag.
2. Check any existing `COPILOT_MAX_REQUEST_BYTES` and `RELAY_IMAGE` settings.
   An explicit 16 MiB cap or an older image override is not replaced by a
   source update or by the new Compose default.
3. If desired, enable terminal size-error handling for Codex with
   `COPILOT_CODEX_TERMINAL_PAYLOAD_ERRORS=1`. This remains off by default
   and does not shrink oversized requests.
4. Configure an earlier per-model compaction threshold only as a deliberate,
   separately qualified policy. It is not enabled by this release.
5. In an approved quiet maintenance window, recreate the relay using the
   verified image with `--no-build --pull never`. Verify the running image,
   effective settings, liveness and both required readiness routes.

See [operations](../operations.md), [compaction policy](../compaction.md#request-byte-limits),
and [release qualification](../compatibility.md#release-checklist) for exact
procedures. Existing conversations may still need manual compaction or a
concise handoff if their serialized history is already too large.

## Qualification and limitations

Local release-candidate checks on November 18, 2026 passed: 773 Python tests,
99% package coverage, 242 PowerShell assertions, lint, documentation examples
and links, lock/environment consistency, and Compose safety checks. Linux ARM64
builds restored locked packages into fresh project environments; base-image
and build caches were available, so this is not a cache-cold build claim.
The production image passed non-root/runtime-only smoke, idle and active-stream
graceful shutdown, and offline rollback-adapter checks. All 15 installed Python
module hashes match the release source, and package/distribution metadata both
report 0.7.0. No container-registry publication is included.

The final release source must pass the configured lint, Python coverage,
PowerShell helper, documentation, lock/environment, Compose and image checks.
Hosted CI must pass on the release commit before publication. Source review,
metadata readiness, and unit tests do not establish end-to-end client recovery.

- The compatibility policy targets inspected Codex CLI 0.170.0 behavior;
  other client versions require qualification.
- Automatic compaction triggering, retained task constraints, and
  post-compaction tool continuity remain separate client-level acceptance
  items. No new broad desktop qualification is claimed.
- Native error events already inside HTTP 200 SSE streams are still passed
  through, not rewritten.
- JSON whitespace probes establish a transport boundary for that tested
  route, not support for a model prompt containing the same number of
  meaningful text bytes.
- Synthetic compaction stays disabled by default. The release neither
  deletes opaque reasoning state nor silently drops tool-call/result pairs.
